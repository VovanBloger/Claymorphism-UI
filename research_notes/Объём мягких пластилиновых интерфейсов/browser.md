# Браузерный рендеринг пухлого пластилинового объёма

Исследование 2026-11-17. Область: рельеф поверхности, фаска, боковая стенка и контактная тень; текущая одобренная текстура зафиксирована и не изменяется. Production-код во время этого исследования не редактировался. Ниже факты отделены от проектных выводов; производительность вариантов ещё не измерялась.

## 1. Почему один набор inset-теней ограничивает объём и что сейчас делает проект

### Takeaway

`box-shadow` хорошо рисует контакт и несколько полос светотени, но не моделирует трёхмерную поверхность с нормалями. В проекте уже есть шесть слоёв и три масштаба: следующий выигрыш следует искать в отдельной форме скруглённой боковины и верхней поверхности, а не в дальнейшем затемнении внешней тени.

### Cited Findings

- Внешняя тень строится от border-box, внутренняя — от padding-box и обрезается его границей. Первая перечисленная тень рисуется поверх следующих; тени не меняют layout. Blur ограничен гауссовой аппроксимацией, а не произвольной кривой освещения. Это задаёт возможности и пределы одного inset-слоя. [CSS Backgrounds and Borders 3, §6.1](https://www.w3.org/TR/css-backgrounds-3/#box-shadow).
- В текущем коде `CLAY_LAYERS` хранит foundation/control/detail и шесть проходов: ambient, contact, crest, shoulder, lip, falloff. После последней калибровки control имеет crest 1.8/2.5/2.7px, shoulder 4/5/7px, lip −1.5/−3.5/3.5px; наружные opacity .18/.16. `getClayLayerCss` добавляет локальный `--clay-layer-scale` поверх общего `--clay-volume`. [Текущий clayLayers.ts](</D:/Projects/ClayCraft ui - дизайн система и генератор soft 3D claymorphism/src/utils/clayLayers.ts>).
- `computeClayStyles` использует те же профили, но связывает локальный depth одновременно с размером всех полос, а blurSoftness — со всеми blur. Рельеф `recessed` остаётся отдельной тройкой. Готовые CSS-строки встраиваются в React/CSS-экспорт. [Текущий clayEngine.ts](</D:/Projects/ClayCraft ui - дизайн система и генератор soft 3D claymorphism/src/utils/clayEngine.ts>).
- В reference CSS присутствует старое базовое описание `.ref-surface` и последующий generated-блок, который переопределяет физические роли. Источник generated-блока — `clayLayers.ts` плюс генератор; build вызывает `material:check`. Поэтому новая формула должна меняться в источнике, а не вручную в нижнем CSS-блоке. [reference-clay.css](</D:/Projects/ClayCraft ui - дизайн система и генератор soft 3D claymorphism/src/components/reference-clay.css>), [generate-clay-materials.ts](</D:/Projects/ClayCraft ui - дизайн система и генератор soft 3D claymorphism/scripts/generate-clay-materials.ts>), [package.json](</D:/Projects/ClayCraft ui - дизайн система и генератор soft 3D claymorphism/package.json>).
- У baseline CSS нет отдельной поверхности, которая могла бы иметь собственное положение начала выпуклости: широкая белая полоса и тёмная полоса накладываются на одну и ту же заливку. Это наблюдение по коду, не результат измерения изображения. [computeLayerShadowLayers](</D:/Projects/ClayCraft ui - дизайн система и генератор soft 3D claymorphism/src/utils/clayLayers.ts>).

### Inferences

- Причина «плоской плитки с обводкой» может быть геометрической: узкая полоса на самом краю показывает контур, а не плавный склон внутрь формы. Увеличение alpha делает контур заметнее; увеличение только blur превращает его в широкую белую дымку. Нужны независимо управляемые ширина склона, положение гребня и высота нижней губы.
- Один глобальный volume следует сохранить, но локальная роль должна определять разные отношения **ширины фаски / толщины стенки / контактного зазора**. Общая светотень не означает одинаковую фаску на карточке 300px и кнопке 44px.
- Наружную тень лучше заморозить на текущем деликатном уровне в первом сравнении. Иначе нельзя понять, улучшилась форма или просто вырос контраст вокруг неё.

### Gaps

- По исходникам нельзя установить, какой вариант ближе к референсу. Нужен одинаковый набор форм, размеров, цветов, текстуры и внешней тени в трёх вариантах.
- Текущий standalone legacy export использует `var(--clay-texture-image, none)`, а generated reference CSS содержит default URI. Это известное незавершённое расхождение экспорта; в исследовании не исправлялось и не является предложением менять одобренную текстуру. [clayEngine.ts](</D:/Projects/ClayCraft ui - дизайн система и генератор soft 3D claymorphism/src/utils/clayEngine.ts>), [reference-clay.css](</D:/Projects/ClayCraft ui - дизайн система и генератор soft 3D claymorphism/src/components/reference-clay.css>).

## 2. Что дают CSS-поверхности, SVG lighting и отдельные рендереры

### Takeaway

Самый дешёвый по сложности внедрения путь — сохранить HTML-контролы и добавить изолированные декоративные слои. CSS face/rim подходит обычным скруглённым формам; SVG height-map обеспечивает более связное освещение сложного силуэта, но требует аккуратного фильтра, явной области обработки и браузерной проверки.

### Cited Findings

- CSS `mask-composite: exclude` оставляет непересекающиеся области масок; свойство отмечено MDN как широко доступное с декабря 2023. Оно позволяет вырезать внутренность круглой рамки без дополнительной непрозрачной заливки центра. [MDN mask-composite](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/mask-composite).
- `::before` — генерируемый дочерний декоративный бокс; он не является универсальной заменой обёртке для replaced-элементов вроде `<img>`. Поэтому для нативного range/input безопаснее декорировать существующий внешний контейнер, сохраняя сам input. [MDN ::before](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Selectors/::before).
- `pointer-events:none` пропускает указатель к элементу под декоративным слоем. Это не отключает клавиатурный фокус для обычного фокусируемого DOM-элемента, поэтому декоративным span нельзя добавлять tabindex. [MDN pointer-events](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/pointer-events).
- `feDiffuseLighting` берёт alpha как bump map и возвращает непрозрачную карту освещения; `feSpecularLighting` использует ту же высоту и компоненту Phong для блика. Эти примитивы широко доступны; по умолчанию расчёт цвета идёт в linearRGB, sRGB задаётся явно. [MDN feDiffuseLighting](https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Element/feDiffuseLighting), [MDN feSpecularLighting](https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Element/feSpecularLighting).
- В спецификации высота задана как `Z=surfaceScale*alpha`; нормаль получается из градиента высоты. Фильтр обрабатывает изображение элемента вместе с детьми. Filter region и primitive subregion являются жёсткими границами обрезки промежуточных изображений. [Filter Effects 1: lighting и filter region](https://www.w3.org/TR/filter-effects-1/).
- `filterUnits` задаёт координаты области фильтра, `primitiveUnits` — координаты длин внутри примитивов. Их нельзя путать: относительная область вокруг элемента может сочетаться с пиксельной шириной фаски. [MDN filterUnits](https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Attribute/filterUnits), [MDN primitiveUnits](https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Attribute/primitiveUnits).
- Стоимость обновления зависит от этапов style/layout/paint/composite. Transform и opacity могут обновляться при композиции отдельного слоя; это не доказательство, что любой SVG-фильтр или тень автоматически исполняются бесплатно на GPU. [MDN animation performance](https://developer.mozilla.org/en-US/docs/Web/Performance/Guides/Animation_performance_and_frame_rate).
- CSS Painting API позволяет рисовать `paint()` как фон по вычисленным стилям, но MDN отмечает API как experimental и limited availability. [MDN CSS Painting API](https://developer.mozilla.org/en-US/docs/Web/API/CSS_Painting_API).
- Canvas допускает кеширование повторяемой графики и разделение статических и движущихся слоёв; OffscreenCanvas может вынести рендеринг в worker. Это требует дополнительного JS-цикла и передачи размеров/настроек вместо декларативной CSS-поверхности. Последнее — вывод для архитектуры проекта. [MDN optimizing canvas](https://developer.mozilla.org/en-US/docs/Web/API/Canvas_API/Tutorial/Optimizing_canvas), [MDN OffscreenCanvas](https://developer.mozilla.org/en-US/docs/Web/API/OffscreenCanvas).
- WebGL требует контроля памяти и обработки context loss; переносимого запроса общего доступного объёма VRAM нет. [MDN WebGL best practices](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/WebGL_best_practices).

### Inferences

| Подход | Что выигрываем | Что усложняется | Предварительное решение |
|---|---|---|---|
| Шесть inset/outset, как сейчас | Минимальная разметка, копируемый CSS, знакомое управление светом | Все световые полосы привязаны к одной границе; произвольная форма склона отсутствует | Оставить baseline и простой fallback |
| CSS face + rim | Независимые плечо, лицевая поверхность и нижняя губа; responsive без измерений | Ещё 1–2 декоративных слоя, stacking, конфликты существующих pseudo-элементов | Основной кандидат для капсул/плиток/карточек |
| SVG alpha height-map | Связная нормаль и свет по силуэту, аккуратный круглый склон | Filter buffers, IDs, CSS→SVG настройки, clip-region, визуальное равенство браузеров | Кандидат для сложных силуэтов и образцового уровня качества |
| PaintWorklet | Собственный SDF/нормаль без DOM-декора | Ограниченная поддержка + модуль worklet + fallback | Не основной путь библиотеки |
| Canvas/OffscreenCanvas | Полный контроль растра и кеша | DPR, resize, worker/JS, экспорт, сохранение HTML-семантики отдельно | Не оправдан для обычных контролов |
| WebGL | Настоящий 3D/PBR и управляемые нормали | Контексты, GPU-память, canvas-композиция, значительно больший runtime | Не вводить для этого исправления |

SVG-прототип: `SourceAlpha → erode → blur → height`; diffuse и specular рассчитываются от height, объединяются с исходным цветом, результат обрезается исходной alpha. Erode отодвигает склон от самой внешней границы; blur сглаживает его. Нельзя фильтровать весь button: его текст и иконка также станут частью height-map. Фильтровать только `::before`/декоративный span; внешний контакт оставить CSS-тенью на основном элементе. Это проектная гипотеза, которую проверяет сравнительный стенд.

### Gaps

- Нет измерений, подтверждающих преимущество SVG, CSS masking или Canvas по FPS/энергии именно на этой странице и реальных мобильных устройствах. Не обещать «GPU ускорение» и фиксированные 60fps без профиля.
- В исследовании не проверялись Safari/Firefox, печать и HTML→PNG export с URL-фильтром. Baseline отдельных примитивов не доказывает отсутствие проблем в их конкретной комбинации.
- CSS `var()` нельзя автоматически считать валидным в каждом числовом SVG-атрибуте. Для выбранного варианта нужен явный адаптер состояния света к числам azimuth/elevation/surfaceScale; работоспособность должна проверяться отдельным реальным рендером.

## 3. Рекомендуемый путь для проекта, экспорт и критерии приёмки

### Takeaway

Сначала сравнить три статических реализации с зафиксированной текстурой. Для production предпочесть CSS face/rim, если он визуально достигает эталона; SVG lighting внедрять только при доказанном преимуществе изображения и приемлемом профиле. Общие роли и генератор остаются источником параметров.

### Cited Findings

- Существующие `materialShadow/materialBackground` централизуют CSS-векторы и направление градиента, а `getMaterialVariables` выставляет общий свет. Это пригодная точка интеграции, отдельная панель для каждого элемента не нужна. [materialStyle.ts](</D:/Projects/ClayCraft ui - дизайн система и генератор soft 3D claymorphism/src/utils/materialStyle.ts>), [materialSettings.ts](</D:/Projects/ClayCraft ui - дизайн система и генератор soft 3D claymorphism/src/utils/materialSettings.ts>).
- В проекте уже существует проверка самодостаточного React-экспорта через esbuild и CSS-генератор с material:check. Новые декоративные слои должны входить в эти артефакты, иначе библиотека и экспорт разойдутся. [materialStyle.test.ts](</D:/Projects/ClayCraft ui - дизайн система и генератор soft 3D claymorphism/src/utils/materialStyle.test.ts>), [clayEngine.test.ts](</D:/Projects/ClayCraft ui - дизайн система и генератор soft 3D claymorphism/src/utils/clayEngine.test.ts>).

### Inferences

1. **Сохранить контракт ролей.** Дополнить profile параметрами face inset, shoulder width, lip height; не подменять physical level DOM z-index. Foundation оставляет широкую полку, control — скруглённую стенку, detail — короткую фаску. Текст и PNG не получают прямоугольную подложку.
2. **CSS-кандидат.** Основной бокс сохраняет внешний контур, размеры, фон и контакт. Декоративная лицевая поверхность располагается внутри, радиус концентрически уменьшается; узкий светлый crest находится на переходе, а нижняя цветная губа остаётся частью исходной формы. При необходимости маска выделяет только кольцевую полосу, чтобы не выбеливать центр. Все слои `pointer-events:none`; текст рисуется выше.
3. **Текстура заморожена.** Использовать существующий `--clay-texture-image`, режим смешивания, tile size и интенсивность. Не менять генератор текстуры, зерно, seed или alpha во время сравнения рельефа. Этим текстура не становится ещё одним неконтролируемым фактором.
4. **SVG-кандидат.** Разделить base/height/light и content. Поддержать три фильтра по уровням, уникальные IDs при экспорте нескольких компонентов. Общий свет меняет числа в definitions, внешняя тень использует тот же CSS-вектор. Не добавлять новый requestAnimationFrame для статического освещения; обновлять при смене настроек/размера только если это необходимо.
5. **Responsive.** CSS-слои используют inset/radius и наследуют размер родителя. В SVG предпочтительны пиксельные primitiveUnits и ограниченная относительная filter region. Избегать растягивания одной фиксированной bitmap-фаски на широкую капсулу: отношение высоты/ширины меняет характер склона.
6. **Самодостаточность экспорта.** CSS-вариант экспортирует класс, pseudo-слои и переменные со значениями по умолчанию. React-вариант включает те же стили либо документированную CSS-вкладку. SVG-вариант дополнительно включает defs и один небольшой адаптер света; не оставляет import внутреннего helper проекта. Старые export fixes не откатывать.
7. **Сравнение.** Для каждого варианта одинаковые lavender panel, coral Confirm, blue toggle, cream knob, mint status и heart. Снять обычный масштаб 1× и увеличенный фрагмент; смотреть ширину плеча, губу, насыщенность центра, отсутствие обводки, отделение объекта от основы. Не оценивать объём только по размеру cast-shadow.
8. **Проверка поведения.** Фактический DOM hit target, фокус, клики и размеры до/после одинаковы; a11y-имена не меняются. Проверить свет из четырёх углов, маленькие 32–44px детали, длинную кнопку, узкий viewport, два DPR; внешний ореол не обрезается. Существующие motion-кривые не менять до выбора материала.
9. **Профиль.** После выбора визуального кандидата сравнить paint time/paint area и память на одной и той же сцене. Анимировать существующий transform/opacity; не анимировать stdDeviation/surfaceScale каждого компонента каждый кадр. Это предложение проверки, а не уже полученный результат.
10. **Форма склона для следующего прототипа.** Смежное оптическое исследование предлагает четверть эллипса `h(d) = H sqrt(2u − u²)`, где `u = d/w` до `d = w`, после чего начинается плоская площадка. Для света `normalize(−.55, −.7, 1.25)` и принятой там ориентации сечения положение specular-пика оценивается как `d* = w [1 − m / sqrt((H/w)² + m²)]`, `m = .3197`: для control `w=10, H=5.5` получается 4.97px внутрь, для foundation `w=20, H=10` — 9.23px. Это расчётная модель, а не измеренная геометрия референса. Текущий лабораторный SVG `erode → blur` лишь приближает склон; он не реализует эту функцию точно. [Оптический анализ и допущения](</D:/Projects/ClayCraft ui - дизайн система и генератор soft 3D claymorphism/research_notes/Объём мягких пластилиновых интерфейсов/optics.md>).

### Gaps

- Изолированный стенд `output/qa/clay-volume-study.html` создан, генератор — `output/qa/generate-clay-volume-study.tsx`. В нём три одинаковые сцены: текущий материал, CSS face/rim и SVG height lighting. Это не production-изменение и не принятый дизайн. Генерация файла завершилась успешно; визуальная проверка передана основному агенту.
- Итоговое решение между CSS face/rim и SVG требует просмотра этого стенда. До этого нельзя честно утверждать, что более сложный рендер визуально лучше.
