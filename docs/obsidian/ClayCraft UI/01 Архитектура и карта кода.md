# Архитектура и карта кода ClayCraft UI

Источник: текущие файлы проекта, 2026-11-14.

## Поток данных

`App` владеет `activeTab` и `GeneratorConfig`. Библиотека передаёт идентификатор компонента через `onInspect`. App меняет конфигурацию и открывает генератор. `ComponentGenerator` вычисляет внешний материал через `computeClayStyles`, показывает интерактивный компонент и вызывает `generateComponentCode` для выбранной вкладки кода.

## Контракт экспорта новых компонентов

`generateComponentCode(config, format, referenceExports?)` получает исходники новых компонентов через третий аргумент. `ComponentGenerator` импортирует `ReferenceElements.tsx?raw` и `reference-clay.css?raw` средствами Vite и передаёт строки движку. Сам движок не импортирует Vite-only raw-модули: его можно тестировать через Node/tsx.

React-вкладка возвращает полноценный TSX-модуль с `ReferenceElement`, его зависимостями и `GeneratedClayComponent`. Нужны `react` и `lucide-react`. CSS нужно сохранить соседним файлом `reference-clay.css`. Экспортируется общий модуль с семью вариантами, а не только минимальный код одного варианта; это осознанное упрощение переносимости.

CSS-вкладка содержит внешний `.clay-element` с вычисленными значениями и общий материал новых элементов. React-обёртка получает те же вычисленные значения inline, внутренние семантические детали имеют свои цветовые варианты.

JSON-вкладка фиксирует компонент, палитру внешней поверхности, геометрию, слои теней, исходный ассет и общие параметры движения. Это не сериализация текущего демо-состояния корзины/календаря и не полный список всех CSS-токенов вложенных деталей.

## Ограничения параметров

У новых составных компонентов палитра, радиус, padding и рельеф генератора влияют на внешнюю подложку. Цвета внутренних кнопок, сумки, гантели, колец и статусов сохраняются по референсам. Выбранный PNG-ассет и тексты метрики/CTA у этих семи типов не подменяют внутреннюю композицию. Заголовок используется товаром, тренировкой и календарём. Не обещать пользователю универсальную перекраску всех деталей.

## Зависимости и сборка

При первой установке обнаружен реальный peer-конфликт: Vite 8.3.8 не совместим с прямой зависимостью esbuild ^0.25.0. Исправлено на ^0.28.2; добавлен package-lock.json. `npm install` завершился, audit на момент установки: 0 vulnerabilities. Это результат конкретной установки, не постоянная гарантия.

Vite-конфиг использует `import.meta.dirname`, чтобы не зависеть от deprecated __dirname при native config loader. Сборка остаётся SPA без серверных функций. Предупреждение о JS-чанке >500 kB остаётся задачей оптимизации, не ошибкой сборки.

## Общий каркас дашборда · 2026-11-14

ReferenceShowcases теперь владеет activeScene: dashboard | login | icons | library. Sidebar вынесен из условной ветки dashboard в общий каркас и остаётся смонтированным во всех четырёх сценах. ReferenceLibrary подключена внутри правой колонки. App не содержит отдельного activeTab=library; основной initial tab — references (в UI Дашборд).

Пункты музыкального меню возвращают сцену dashboard; три пункта Разделов студии выбирают соответствующую сцену, с aria-current=page. selectScene сбрасывает страницу к верху при переходе. На desktop от 1024 px sidebar sticky/top16 с ограничением высоты viewport и собственным вертикальным скроллом; на mobile панель остаётся частью общего вертикального layout. ClayBottomNav поддерживает 3 пункта без пустой четвёртой ячейки.

## Единый управляемый каркас всех разделов · 2026-11-14

Актуальный DashboardSection: dashboard | login | icons | library | generator | design-system. Выбранная сцена теперь хранится в App вместе с GeneratorConfig и передаётся в ReferenceShowcases через activeScene/onSelectScene. Локальный state выбора сцены удалён; каркас всегда смонтирован. ComponentGenerator и DesignSystemGuide рендерятся внутри dashboard-content справа от sidebar.

App передаёт onChangeGeneratorConfig, onSelectPresetForGenerator и существующие inspect-callbacks. Переход из карточки библиотеки/маскота в генератор меняет сцену внутри того же каркаса. Настройки остаются в App и не теряются при смене раздела. Компонент ClayBottomNav сохранён для образцов, но глобальный dock убран. Не возвращать генератор/дизайн-систему в условные ветки вне каркаса: это снова скроет меню.

## Изменения структуры · 2026-11-14

ReferenceShowcases: удалён activeNav и шесть демонстрационных категорий, заголовок Dashboard фиксированный. Sidebar состоит из одного пункта Dashboard и пяти разделов студии; premium-блок удалён. На обычных размерах окна overflow отсутствует, overflow-y:auto остаётся аварийным fallback для очень короткого viewport. При высоте до 700px профиль и отступы компактнее без уменьшения шрифта/иконок меню.

ReferenceElements: кольца представлены SVG с уникальными `useId`-идентификаторами градиентов и фильтров (`${ringId}-clay` и `${ringId}-track`). Отдельный сдвинутый нижний торец убран: вместо него используется единый путь прогресса на кольцо (`r=99/73.5/48`, `strokeWidth=21`) с фильтром на базе эродированного ядра/гребня и внутренней маски `innerMask`, что убирает внешнюю обводку и даёт пухлый 3D-объём. `pathLength=100` и `strokeDasharray` задают процент, `.ref-ring-wrap` (`width: 100%; max-width: 226px`) предотвращает выход SVG за границы карточки, число и подпись размещены внутри того же SVG. Новый образец scrollbar и карточка правила анти-контура для SVG-трубок находятся в `DesignSystemGuide`, глобальное оформление нативных полос — в `index.css`.

## Код Sticker Notch

`src/components/StickerNotchNav.tsx` — автономный UI-адаптер, `src/components/sticker-notch-nav.css` — его материал, `src/utils/notchMath.ts` — неизменённые чистые функции геометрии/физики из локального Генератора стикеров. `notchMath.test.ts` переносит 6 исходных тестов. Адаптер не импортирует Telegram, Next.js, haptics и серверные модули.

ComponentGenerator передаёт исходник компонента, математику и CSS в `generateComponentCode` через `referenceExports.notch`. Для TSX-экспорта движок встраивает математику в один модуль и удаляет локальный import; CSS подключается отдельным файлом. Тест компилирует полученный модуль и проверяет отсутствие недоступного import. Параметры движения экспортируются в JSON.
